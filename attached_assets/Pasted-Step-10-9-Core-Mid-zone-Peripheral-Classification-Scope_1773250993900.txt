Step 10.9 — Core / Mid-zone / Peripheral Classification

Scope Statement

Implement ONLY Step 10.9 inside the Discursive Concepts tab.

This step updates the classification logic used by the Core vs Peripheral Quads panel so that it becomes a three-way classification:

- Core
- Mid-zone
- Peripheral

Do not redesign the panel.
Do not refactor the surrounding system.
Do not revisit earlier steps.

Do NOT Change Rules

Do NOT change:

- quad extraction logic
- quad frequency calculations
- temporal slicing logic
- Sankey logic
- constellation similarity logic
- similarity matrix logic
- constellation clustering logic
- corpus loading pipeline
- speeches-only discursive modelling rule
- Lexical tab
- Semantic tab
- routing
- layout
- CSV export behaviour
- Top 20 / Top 50 / Top 100 / All display controls
- sorting by Total Frequency

Goal

Update the existing binary classification rule so the panel uses a three-way LDNA-style interpretive classification.

New rule:

- Core:
  frequency > median
  AND
  slices ≥ 2

- Peripheral:
  frequency = 1
  OR
  slices = 1

- Mid-zone:
  all remaining quads

This step modifies classification logic only.
All other behaviour must remain unchanged.

Implementation Instructions

1. Locate the existing classification logic used by the Core vs Peripheral Quads panel inside:
   - client/src/pages/Analysis.tsx

2. Identify the current logic that assigns a status/category based on:
   - frequency > median
   - slices ≥ 2
   and currently outputs only:
   - Core
   - Peripheral

3. Replace only that status assignment logic with the new three-way rule:

   - if frequency > median AND slices >= 2 → "Core"
   - else if frequency === 1 OR slices === 1 → "Peripheral"
   - else → "Mid-zone"

4. Preserve all existing computed inputs exactly as they already exist:
   - total frequency
   - slice count
   - median calculation
   - row sorting
   - row limiting
   - CSV export dataset

5. Update the displayed status column so it can show:
   - Core
   - Mid-zone
   - Peripheral

6. Do not rename the panel unless absolutely necessary.
   If the panel title currently says “Core vs Peripheral Quads”, leave it unchanged for this step unless the title text is directly tied to the logic in a way that causes confusion in the rendered UI.
   If you must update the visible label, make the smallest possible wording change only.

7. Do not alter table layout, dropdown controls, export button logic, or surrounding explanatory text unless a tiny wording adjustment is required to reflect the new status values.

8. Make the smallest possible code change.
   Do not refactor nearby hooks, memo blocks, helper functions, or render structure unless strictly necessary for the status update.

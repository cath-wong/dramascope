STEP 48 — Corpus Composition and Provenance Summary

Goal

Add a transparent corpus-composition summary so that users can see how the currently selected corpus is distributed across playwrights before interpreting analytical results.

This is a methodological-transparency and provenance enhancement.

Do NOT introduce new analytical methods.

The purpose is to make corpus imbalance and source composition visible, especially when multiple playwrights are selected.

Cost / Agent Efficiency

Keep this task targeted.

- Reuse the playwright and temporal filtering architecture established in STEP 45–47.
- Inspect only Dashboard, shared scope/filter state, and any small reusable summary component needed.
- Do not perform a broad codebase investigation.
- Do not re-read Analysis.tsx unless a shared scope display genuinely requires it.
- Do not take screenshots unless needed to diagnose a UI issue.
- Make the smallest coherent change.
- Run one final TypeScript check only if code is modified.
- Do not fix unrelated pre-existing TypeScript errors.

1. Add Corpus Composition to the Dashboard

Add a new Dashboard section titled:

CORPUS COMPOSITION

or:

Corpus Composition

Place it after the existing top-level corpus summary cards and before detailed analytical or time-distribution sections, whichever fits the current Dashboard hierarchy best.

Do not redesign the overall Dashboard.

The section should show the composition of the active corpus by playwright.

---

2. Active-Scope Behaviour

The composition summary must respect the current shared corpus filters.

It must update when the user changes:

- selected playwrights;
- date range;
- Corpus Scope where applicable;
- individual play selection where applicable.

For example:

All playwrights + full range
→ show all eight playwrights.

Shakespeare + Marlowe
→ show only Shakespeare and Marlowe.

All playwrights + 1590–1600
→ show only playwrights represented in that temporal range.

Individual Play
→ show the single relevant playwright/play scope appropriately.

Do not calculate composition from raw unfiltered DataContext arrays if the active scope is narrower.

Reuse the existing selectedLines / selectedSpeeches architecture.

---

3. Metrics by Playwright

For each playwright represented in the active corpus, show:

- Playwright
- Number of plays
- Lines
- Speeches
- Share of active lines (%)
- Share of active speeches (%)

Where practical, also show:

- earliest year_est represented
- latest year_est represented

Use dynamically calculated values.

Do not add token totals by playwright in this step unless they are already readily available without requiring another expensive full-corpus tokenisation pass.

Avoid introducing unnecessary computation.

---

4. Relative Shares

Calculate:

Line Share % =
playwright lines / total active lines × 100

Speech Share % =
playwright speeches / total active speeches × 100

Round sensibly for display, for example to one decimal place.

Do not use these shares as analytical normalisation elsewhere in this step.

They are descriptive corpus-composition indicators only.

---

5. Visual Representation

Use a compact and transparent visualisation.

Preferred approach:

- a sortable table;
- plus simple proportional bars inside the share columns if this fits the current Dashboard style.

Do not add a complex charting library.

Do not add pie charts unless the existing Dashboard design strongly favours them.

The user should be able to compare corpus contribution across playwrights at a glance.

Keep the visual design consistent with existing DramaScope tables and summary cards.

---

6. Sorting

Allow the composition table to be sorted by at least:

- Playwright
- Number of plays
- Lines
- Speeches
- Line Share %
- Speech Share %

Default sort:

Lines descending

or, if more consistent with the existing Dashboard:

largest corpus contribution first.

Do not add unnecessary filtering controls within this table.

---

7. Provenance / Interpretation Note

Add a concise methodological note immediately below or above the table.

Suggested meaning:

Corpus size varies across playwrights. Composition should be considered when interpreting raw frequency and distributional results; relative-frequency measures are preferable for direct comparison across unequal corpus subsets.

Do not present this as a warning or error.

Keep it concise and neutral.

Do not claim that corpus imbalance invalidates comparison.

---

8. Play-Level Provenance

Do not add a full second play-level composition table in this step.

However, ensure that the playwright-level “Number of plays” is based on unique play_id values.

Do not count titles by string alone if play_id is available.

playwright

10. Performance

Do not:

- tokenise text;
- generate n-grams;
- call Semantic or Discursive analytical functions;
- perform expensive corpus rescans beyond simple metadata aggregation.

The Dashboard must remain responsive for All playwrights.

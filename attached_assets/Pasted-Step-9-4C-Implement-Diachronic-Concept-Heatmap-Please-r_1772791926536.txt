Functional requirements

1. Placement
- Add the heatmap as a new panel below the Sankey panel inside the Discursive Concepts tab.
- Do not disturb existing panels.

2. Data source
- Use only:
  - results.quadFreqBySliceObj
  - results.sortedSlices
- Do not reprocess speeches, tokens, or windows.

3. Heatmap structure
- Columns = time slices from results.sortedSlices
- Rows = most frequent co-lemmas across all slices
- Recommended row count: top 20

4. Row extraction rule
- For each quadKey in quadFreqBySliceObj:
  - split quadKey into [node, co1, co2, co3]
  - exclude the node
  - collect only co1, co2, co3
- Aggregate counts across all slices to rank co-lemmas
- Build top co-lemma rows from those totals

5. Cell values
- Each cell = frequency/count of that co-lemma in that time slice
- Derive this from quadFreqBySliceObj by summing counts for quads in that slice that contain the co-lemma in co1/co2/co3

6. Rendering
- First version must be a stable HTML/CSS heatmap grid or table
- Do NOT use D3 for this step
- Cell colour intensity should scale by count
- Include a small legend or label for intensity if easy, but keep it simple and robust

7. Interaction
- Clicking a heatmap cell must:
  - set the active slice
  - filter/highlight the Quad Inventory to quads from that slice containing the selected co-lemma
  - preserve existing traceability/examples behaviour
- Do not redesign the inventory; layer this interaction onto existing filtering state if possible

8. Export
- Add CSV export for the heatmap data
- At minimum provide one export format:
  - wide format: row = lemma, columns = slices
- Long format is optional if easy

9. State / implementation quality
- Use memoised derived data where appropriate
- Guard against empty results
- Do not crash if a slice has no data
- Keep the implementation incremental and local

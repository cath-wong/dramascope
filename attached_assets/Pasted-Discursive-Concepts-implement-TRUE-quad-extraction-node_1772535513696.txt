Goal: In Discursive Concepts, compute and expose actual quads as 4-lemma sets (node + 3 co-lemmas) derived from each node occurrence window.

1) Definitions (hard constraints)

Dataset: speeches only.

Preprocessing: existing processTokens(text_raw, { useStoplist, useLemmas }).

Window: node-centred symmetric ±50 tokens around each node occurrence; overlaps allowed.

Quad (true): for each node-window, take the top 3 most frequent co-lemmas within that window (excluding node), then form the 4-lemma set:

{node, c1, c2, c3} sorted for stability.

We build many quad instances across windows and aggregate them.

Keep up to 5 instances per quadKey (per slice or globally) for drill-down.

3) How to compute quads (replace/extend current cooc logic)

Currently you compute coocInSlice by aggregating neighbours across node indices in a speech.

Instead, do it per node occurrence:

For each speech s:

compute nodeIndices as you already do

for each node index:

compute winTokens = tokens[idx-50 : idx+50]

build winCounts = Map<lemma, count> for tokens in winTokens excluding node

sort winCounts desc

take top 3 neighbours (if <3, skip this window)

build quad = [node, n1, n2, n3] then sort lexicographically for stable key

quadKey = quad.join("|")

push a QuadInstance into quadInstancesBySlice.get(slice)

increment quadFreqBySlice.get(slice).set(quadKey, +1)

add up to 5 examples in quadExamples for that quadKey
Also increment totalNodeWindows regardless; but increment totalQuadWindows only when a quad was formed (>=3 neighbours). Expose both counts.

Important: this is now “true quad extraction” and must replace any text that implies you’re only doing pair co-occurrence.

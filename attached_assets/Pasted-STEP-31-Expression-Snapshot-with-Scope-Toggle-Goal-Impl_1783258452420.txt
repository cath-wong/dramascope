STEP 31 — Expression Snapshot with Scope Toggle

Goal

Implement the first real analysis in the Semantic tab: Expression Snapshot.

This step introduces a transparent expression-candidate extraction layer with two analytical scopes:

1. Node-centred expressions
2. Corpus-wide expressions

Both scopes must use the same underlying extraction logic:

tokenise → generate contiguous n-grams → count → rank

The only difference is scope:

- Node-centred mode keeps only n-grams containing the selected node lemma.
- Corpus-wide mode keeps all eligible n-grams.

This step must NOT implement formulaicity, fossilisation, entrenchment, or diachronic change yet.


IMPORTANT

Do NOT modify:

- Data loading

- quad extraction logic
- Discursive Dashboard v1.0 logic

Do NOT add:

- formulaicity scoring
- collocation association measures
- MI / logDice
- conventionalisation metrics
- diachronic expression analysis
- expression family clustering
- semantic interpretation summaries

This step is Expression Snapshot only.


Scope

Apply ONLY to:

client/src/pages/Analysis.tsx

Focus ONLY on the SemanticTab component.

Do NOT touch LexicalTab or DiscursiveTab.


Analytical Object

Expression candidate

Definition:

A contiguous multi-word sequence extracted from the corpus and treated as a candidate expression when it recurs above the selected frequency threshold.

At this stage, these are expression candidates, NOT confirmed formulaic expressions.


Analytical Scopes

Add an Expression Scope control with two options:

1. Node-centred

Description:
Only expressions containing the selected node lemma are extracted.

Example:
For node lemma “lord”:
- my lord
- good my lord
- lord jesus christ

2. Corpus-wide

Description:
All recurring expressions are extracted, regardless of whether they contain the selected node lemma.

Example:
- father son holy ghost
- by my faith
- good my lord

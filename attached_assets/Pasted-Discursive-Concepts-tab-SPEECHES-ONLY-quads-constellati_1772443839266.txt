4) Define “co-occurrence pairs” within a speech window

Default modelling window = one speech row.

Within each speech:

take token list after preprocessing

restrict to first tokenSpan tokens (default 100), or full speech if shorter

build pair co-occurrence counts within that span:

Pilot-friendly rule:

count all unordered pairs that occur in the same span (i < j), but to avoid O(n^2) blow-up:

Use a local window within the span (e.g., ±10 tokens) OR

Use unique tokens in span and count pair once per speech
Choose ONE approach and document it in a short “Preprocessing note” in code comments + UI tooltip.

Recommended for performance + interpretability:

Unique-token-in-speech approach:

get unique tokens from the span

each unordered pair gets +1 count for that speech
This produces stable co-occurrence without heavy computation.

Store for each speech:

localPairs: Map "a|b" → count (usually 1 in unique-token approach)

5) Quad extraction (LDNA-inspired pilot)

Operational definition:

For each speech window:

Compute pair scores (use count; PMI optional but not required).

Select top P pairs by score (default P=20; if fewer pairs exist, use all).

Form candidate quads:

choose two distinct pairs that share one lemma

union of their terms must yield 4 unique lemmas

quad terms are sorted alphabetically to deduplicate

Deduplicate quads within the speech.

For each quad, store metadata:

window_id (unique, e.g. row index or stable hash)

title, play_id if present

act, scene, speaker

timeSlice

quad_terms (t1,t2,t3,t4)

supporting_pairs (optional: the two pairs used)

This is not a 4-gram; do not rely on adjacency.
